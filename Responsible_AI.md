# Responsible AI Report – Employee Attrition Prediction System

## 1. Purpose

The Employee Attrition Prediction System is a machine learning application developed to estimate employee attrition risk using employee-related attributes.

The system uses a trained Random Forest classification pipeline and provides prediction, model evaluation, explainability, data drift monitoring, and Responsible AI information through an interactive Streamlit dashboard.

The system is intended for educational and analytical purposes. Its predictions should support human analysis and must not be treated as automatic employment decisions.

---

## 2. Model Overview

- **Problem Type:** Binary Classification
- **Target Variable:** Turnover Status
- **Classes:** Stayed / Left
- **Final Model:** Random Forest Classifier
- **Number of Input Features:** 44
- **Number of Trees:** 150
- **Class Weight:** Balanced
- **Random State:** 42

The deployed model is stored as a scikit-learn pipeline containing preprocessing and classification stages.

Numerical attributes are processed using median imputation and standardization. Categorical attributes are transformed using preprocessing that includes one-hot encoding before being passed to the Random Forest classifier.

The final Random Forest model achieved the following evaluation results during model development:

| Metric | Score |
|---|---:|

| Recall | 99.33% |

## 4. Fairness

Employee attrition models may behave differently across demographic or employment groups.

Relevant group-level evaluation should therefore be performed before the model is used in a real organizational environment.

Potential fairness considerations include:

- Comparing model performance across relevant employee groups.
- Examining false-positive and false-negative rates across groups.
- Reviewing whether particular attributes introduce undesirable bias.
- Repeating fairness evaluation when the model or data changes.
- Avoiding automatic adverse employment actions based on model output.

A numerical fairness score is not reported in the current dashboard because the original evaluation dataset is not currently available for a valid group-level fairness audit.

Therefore, the system does not claim that the model has been proven fair across all employee groups.

## 5. Privacy

Employee datasets may contain personal, organizational, or sensitive workplace information.

A real deployment should apply appropriate privacy safeguards, including:

- Data minimization.
- Collection of only necessary attributes.
- Restricted access to employee information.
- Secure storage and transmission.
- Appropriate data retention and deletion procedures.
- Protection of model inputs, outputs, and logs.
- Avoidance of unnecessary exposure of employee-level predictions.

The current project should not be interpreted as establishing compliance with any specific privacy law or organizational policy.

## 8. Explainability

SHAP (SHapley Additive exPlanations) is used to examine feature contributions to predictions generated by the Random Forest classifier.

The dashboard displays influential transformed model features and their SHAP values.

Positive SHAP values indicate features pushing the prediction toward the attrition class, while negative values push the prediction toward the stay class.

Explainability helps users inspect model behavior, but an explanation does not establish that a feature caused an employee to leave.

## 9. Human Oversight

The system is designed as a decision-support tool.

Model predictions must not be used as the sole basis for:

- Hiring decisions.
- Termination decisions.
- Promotion decisions.
- Disciplinary actions.
- Compensation decisions.
- Other consequential employment actions.

A prediction represents a statistical estimate produced from patterns learned from training data. It does not prove that an employee intends to leave.

Human review and appropriate organizational context should accompany any interpretation of model output.

---

## 10. Data Drift Monitoring

Employee populations and workplace conditions may change over time. Changes in input distributions may reduce the reliability of a deployed model.

The Streamlit dashboard therefore provides a Data Drift Monitoring module.

The module accepts:

1. A reference CSV dataset.
2. A current CSV dataset.

For common numerical features, the system applies the two-sample Kolmogorov-Smirnov (KS) test.

A p-value below 0.05 is treated as a statistical signal that the two observed feature distributions may differ.

A statistical drift signal does not by itself prove harmful model degradation. Drift results should be reviewed together with model performance, data quality, sample size, and operational context.

## 12. Known Limitations

The current system has several limitations:

- Predictions depend on patterns present in the training data.
- Future employee populations may differ from the original training population.
- Model predictions cannot determine an employee's actual intention.
- Correlation learned by the model should not be interpreted as causation.
- Group-level fairness has not been fully audited in the current dashboard because the original evaluation dataset is unavailable.
- Data drift analysis requires valid reference and current datasets.
- High evaluation metrics do not guarantee identical real-world performance.
- Human and organizational factors may not be completely represented by the available features.
